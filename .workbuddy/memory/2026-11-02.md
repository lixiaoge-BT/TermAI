## 教训
- **`setTimeout` 不要随手 unref**：在「只有它维持事件循环」的场景（探针里全是微任务）

- 拆 `useShallow` 时要连 selector 一起改：只给 hook 返回值做浅比较没用，
  高频字段（liveThought）必须从同一个 selector 里移出去。
- 探针里验证「窗口外的命令被重发」需要先把命令真的挤出窗口
  （只读命令要执行 ≥2 次才会被判重复，批量 4 条/步约 7 步即可超过 24 条）。

## 截图「rm: Device or resource busy / 执行失败」定位（17:10）
用户问「是不是因为命令太多」。**不是**。截图里 13 步是**一条** `sudo rm -rf`（8 个路径参数，
无顶层 `;`），0.2s 真执行并返回非 0；若是子命令超限，状态会是「已跳过」+「一行里塞了过多子命令」文案。

真实原因：`/run/containerd/io.containerd.runtime.v2.task/k8s.io/<id>/rootfs` 是 **runc 挂载点**，
`rm` 删不掉挂载点本身 → EBUSY。紧接着 `umount /run/containerd`（父目录，根本不是挂载点）→ `not mounted`。

真实主机实测（root@192.168.188.128，CentOS 7.9 / util-linux 2.23）：
- `rm -rf` 目录含挂载点 → 报 busy，**退出码 1**
- `umount` 父目录 → `not mounted`，**退出码 32**
- `umount` 真挂载点 → 0，再 `rm -rf` → 0
- 该机 `/run` 是 tmpfs（3.9G），`/run` 下 39 个挂载点

**整改**：新增 `busyMountHint(output)`（services/agent.ts），命中 `Device or resource busy /
target is busy` 时把「找挂载点 → umount → 再删；/run 不释放磁盘；容器目录先停 kubelet/containerd；
要释放磁盘看 `df -h`」注入下一轮观察；它与 `probeNote` 互斥地压掉通用连击提示，避免重复说教。
接入点：批量与单条两条观察拼装路径，均 `(probeNote || busyNote ? "" : failTreadmill.note())`。

## 增强「读上下文」（2026-11-02 下午）

用户诉求：增强 Agent 阅读上下文的能力、提高执行准确性。三处引擎级改动：

**1) `focusOutput` 重写（services/agent.ts）**
- 旧实现两个硬伤：① 没有错误关键词就 `text.slice(0, budget)` —— **尾部整段丢弃**，
  而 `systemctl status` / `journalctl` / 编译日志的最终状态、最后一条报错都在尾部；
  ② 有错误但超预算时兜底顺序「错误行 → 头部」，尾部同样会丢。
- 新优先级：① 首行 ② 末行 ③ 错误行（上限 40） ④ 状态行（端口/服务/容量，上限 20）
  ⑤ 剩余预算对半给头部/尾部连续正文。按**字符**逐行装入（装不下就跳，后面短行仍有机会）。
- 省略处写 `…（省略第 a~b 行，共 N 行）`，尾部统一说明「原始 N 行 / M 字符；错误行在第 …；
  文件用 `sed -n 'a,bp' 文件`、命令换更窄参数重取，**不要原样重跑整条命令**」。
- **删掉前置的 `sanitizeOutput(…, 200)` 行数上限**（→ 100000 近乎不生效）：行数收敛和字符
  聚焦是两道闸，行数先砍就轮不到 focus 看见中段错误行。实测 `seq 1 5000` 23892 字符原本会被
  砍到 200 行；现在 40000 行 / 2.7MB 也能保住 37% 与 71% 处的错误行，观察恒 ~7.7k 字符 / 45ms。

**2) 「已截断」判定改为看省略标注，不再比长度**
`sanitizeOutput` 去 ANSI / `\r` / 空行都会让长度变短 → 旧判据 `out.length < rawOut.length`
给几乎所有彩色输出都挂上「输出过长已截断」，模型以为自己缺一半信息，反复换写法重取。
新增 `OMIT_MARK_RE`（`（已省略 N 行中间输出）` / `（省略第 …`）作为唯一判据。
focusOutput 已自带尾部说明时不再重复追加外层 note（原来会打两遍）。

**3) dupTracker 保存 `full`，拒绝时回填完整输出**
模型重发已执行命令多半是「上轮被截断没看清」。旧回填只有 240 字符 digest，越看越少 →
连拒 3 轮任务被杀。现在 `record` 存 `focusOutput(sanitizeOutput(out, 20000), 6000)`，
