## 堡垒机唤起 TermAI —— Jump Connect / Deep Link 实现

**背景**：Brett 把堡垒机 H5 的"外部 SSH 客户端"路径从 xshell 切到 TermAI 后，点 TermAI 图标能弹出 TermAI 但只连到本地终端（host=local），根本不会自动连堡垒机指定的目标主机 + wsupport 账号。

**根因**：TermAI 完全没有"接收外部唤起参数"的入口。
- `package.json` 没注册 `protocols` 块；
- `electron/main/index.ts` 的 `second-instance` 只把窗口抢到前台，**完全不解析第二个进程的 argv**；
- 没有 `app.on('open-url')`（macOS 协议唤起入口）；
- `electron/preload/index.ts` 无任何 deep-link IPC；
- 渲染层 `terminalBridge.__termai_connect` 只能由 UI 主动调用，没有"被外部叫醒"的入口。

由于堡垒机按"Xshell 替代客户端"的调用模式 spawn TermAI.exe，**TermAI 启动时 `process.argv` 里其实已经有连接参数了**（只是 TermAI 不认），加个 parser 就能接住。

### 改了什么

| 文件 | 内容 |
|---|---|
| `electron/main/deepLink.ts` | **新增** argv / URL 解析器。支持 4 种形态：自定义 `termai://connect?...`、Xshell `-url ssh://...`、Xshell `-ssh user@host -pw xxx -p port`、自定义 `--jump host=X port=Y user=Z password=P` |
| `electron/main/index.ts` | 注册 `termai://` 协议、解析首启 `process.argv`、扩 `second-instance` 解析并转发、`open-url` 监听、`jump:connect` IPC 推送（带 pending cache 兜底渲染层未 ready） |
| `electron/preload/index.ts` | `__jump.onJumpConnect(cb)` contextBridge + 暴露 `JumpConnectParams` / `JumpSource` 类型 |
| `src/types/index.ts` | import + re-export 类型，加 `window.__jump` 全局声明 |
| `src/lib/jumpConnect.ts` | **新增** 渲染层收到 jump 后自动 `createSession` + `ensureVisible` + `__termai_connect`，附 8 次重试兜底桥未 ready |
| `src/App.tsx` | `initJumpConnect()` 挂在 `initTerminalBridge()` 之后 |

## 第二轮：Xshell 兼容加固 + host 持久化

Brett 说"按照 xshell 的来，帮我修复"——堡垒机 H5 的"xshell 客户端"按钮配的就是 TermAI.exe，命令行模板是 Xshell 标准的（`-url ssh://...` / `-ssh user@host -pw xxx -p port` / `-newtab`）。

### 改动

1. **`electron/main/deepLink.test.ts`** 新增 15 个测试覆盖真实 Xshell 调用形态：
   - `-url ssh://[user[:pass]@]host[:port]`（含 IPv6/无端口）
   - `-newtab -url ssh://...`
   - `-ssh user@host -pw xxx -p port`
   - `-ssh user@host:port -pw xxx`（端口写在 user@host 后面）
   - `-ssh user@host` 无 -pw 无 -p
   - `termai://connect?host=...&user=...&password=...&port=...`
   - `--jump host=X port=Y user=Z password=P`
   - 裸 `ssh://` URL
   - URL 编码（`%40` / `%21` 等）
   - 无密码 / 空 argv / 无效 -url / 杂项 flag
   - second-instance source 传递

2. **`src/lib/jumpConnect.ts`** 升级：
   - 旧实现：jump 出来的会话是**纯内存**的，关 TermAI 就没了，不像 Xshell
   - 新实现：先 `ensureJumpHost` 把目标主机落到 `useAppConfig.hosts` 持久化（按 `host:port:username` 三元组去重），会话绑到 `hostId`，像 Xshell 那样"打开就在主机列表能看到，下次能复连"
   - 凭据缺失/更新时刷新 password/privateKey
   - `authMethod` 优先 password（堡垒机最常见），有 privateKey 时切到 privateKey

### 修复：日志会泄露明文密码

## 第五轮：端到端冒烟测试抓出 3 个真 bug（已修 + 重打包）

用 `npm start -- -url "ssh://wsupport:testpass@1.2.3.4:22"` 起真实实例做冒烟，暴露三个只在运行时才现形的问题。

### Bug 1（致命）：`did-finish-load` 注册晚于 load，`pendingJumpRequest` 永远推不出去

`electron/main/index.ts` 里 `await win.loadFile(...)` / `loadURL()` 在前，
`win.webContents.on("did-finish-load", ...)` 注册在后 —— await 返回时事件早就触发完了。
**堡垒机首次唤起（也是最主要的那条路径）参数会一直卡在缓存里，渲染层永远收不到。**

修复：把 `did-finish-load` 监听挪到 load 调用**之前**，并在 load 的 await 之后加一次
「已加载则立即补发」的兜底，避免极端时序下再漏。

### Bug 2：Electron 会重排 `second-instance` 的 argv，flag 与值被打散

实测抓到的 argv（原始是 `-ssh wsupport@10.0.0.5 -pw secret123 -p 2222`）：

```
[..., "-ssh", "-pw", "-p", "--allow-file-access-from-files", ..., ".",
 "wsupport@10.0.0.5", "secret123", "2222"]
```

所有 `-xxx` 开关被提到前面、值被拆到最后变成**位置参数**，相邻关系完全失效
→ 端口掉回默认 22、密码丢失。

修复：`parseBareTarget` 增加「散装位置参数」兜底 —— 识别到 `user@host` 这类 target 后，
按位置依次补 port（纯数字 1-65535）和 password（非 flag 非纯数字）。
加了 3 个测试复刻该重排形态。

### Bug 3：`-pw` 脱敏在 argv 重排后失效，明文密码漏进日志

老的脱敏靠「前一个 token 是不是密码 flag」，重排后 `secret123` 不再紧跟 `-pw`，直接明文落盘。

修复：`argvDebug.ts` 改成**按值脱敏** —— 用 parser 解析出的 password 去比对 argv token，
命中就打码；同时保留 flag 相邻判断和 `--flag=value` 内联判断。无论 argv 怎么重排都盖得住。
