## 安装包瘦身 + 安装加速（不改功能）

目标：减小安装包 + 加快安装，功能零变化。结果全部实测。

### 改动（package.json build 段）

1. `electronLanguages: ["zh-CN","zh-TW","en-US"]` — locales 55 → 3 个 .pak，省 36.5MB 解压量。
2. `files` 加负向排除，剔除**已被 vite 打进 dist 的渲染层依赖**：
   react / react-dom / react-router(-dom) / scheduler / loose-envify / js-tokens /
   cookie / set-cookie-parser / lucide-react / xterm / xterm-addon-fit / @xterm /
   zustand / clsx / tailwind-merge。
   依据：主进程只 `import ssh2`（esbuild `packages:"external"`），preload 全 bundle；
   渲染层全走 vite → asar 从 19.45MB 降到 5.26MB。
3. `asarUnpack` 只留 `node_modules/node-pty/**`（原先还列了 ssh2、cpu-features）。
4. `asar: { smartUnpack: false }` — 关键：smartUnpack 会因 cpu-features 带 gyp 把整条
   ssh2 链判成 native 一并解包（29 文件 / 726K）。关掉后 ssh2 收回 asar 内仍可 require。
5. node-pty 瘦身：排除 third_party（conpty 源码 2.5M）、src、scripts、lib/*.test.js、
   prebuilds/darwin-*、prebuilds/win32-arm64（2.5M）、node_modules/**（node-addon-api 编译期头文件）。
   **必须保留** `node-pty/build/Release/conpty/{conpty.dll,OpenConsole.exe}`（运行时用）
   和 `prebuilds/win32-x64/`。

### 踩坑
- **本机 shell 环境带 `ELECTRON_RUN_AS_NODE=1` 和 `NODE_OPTIONS=--require=...shim`**，
  直接跑 electron/打包产物会以纯 Node 模式启动 → 报 `bad option: --remote-debugging-port`
  （报错串来自 exe 内 Node CLI）。必须 `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS`。
- electron-builder 的 `asarUnpack` 无法单独收窄，得先关 `smartUnpack`。
- PowerShell 工具 `Add-Type` 被安全策略拦（不能截屏）；读 `MainWindowTitle` 不受限，
  写 Out-File 再 Read 即可。

## 系统托盘 + 点 X 隐藏（electron/main/index.ts）

需求：启动后常驻托盘、右键菜单可退出、点窗口 X 只隐藏。

实现要点（全部实测）：
- `close` 事件拦截 → `preventDefault()` + `win.hide()`；`isQuitting` 为 true 时放行。
  隐藏不触发 `closed`，所以 `windowBundles` 里的 SSH / 本地终端不会被 dispose，**连接保持存活**。
- `app.on("before-quit")` 与 `app.on("session-end")` 都置 `isQuitting = true`。
  少了任一个都会出现「托盘退出/关机被 close 拦截挡住」。session-end 是 Windows 注销关机专用。
- `window-all-closed` 改成 `if (process.platform !== "darwin" && (isQuitting || !tray)) app.quit()`。
- **`close` 拦截必须带 `|| !tray`**：托盘创建失败时若仍拦截，窗口一藏就再没有入口，
  用户只能去任务管理器。
- 托盘菜单：打开主界面 / 新建窗口 / 分隔线 / 退出。左键单击 `restoreMainWindow()`。
- `second-instance`、`activate` 改走 `restoreMainWindow()`（原实现只 `focus()`，
  对已 hide 的窗口无效 → 堡垒机再唤起时窗口不出现）。
- 首次隐藏用 `tray.displayBalloon` 提示一次（仅 win32），避免用户以为程序没关掉。

**坑：`nativeImage.createFromBuffer` 不解码 ICO** —— 返回 empty 而非抛异常。
dev 下 32x32 实际来自 fallback 的 `icon-32.png`。所以候选链是 ico → icon-32.png → icon-16.png，
判定必须用 `img.isEmpty()`。生产路径 `process.resourcesPath/app.asar/assets/icons/`，
用 `readFileSync` + `createFromBuffer` 读 asar 内文件最稳（`createFromPath` 对 asar 不可靠）。
`createFromPath` 弃用原因见上；验证脚本 `dist-test/verify-tray-icon.cjs`。

实测（生产包 dl-20261106c）：窗口 pid 50268 → CloseMainWindow() → 进程存活 + hwnd=0
→ 二次启动同一 pid 窗口恢复显示。eslint / tsc 全绿。

兼容性：隐藏实例不影响覆盖安装 —— `build/installer.nsh` 的 `customCheckAppRunning`
本来就 `taskkill /f /t`，能杀掉托盘里的进程。

### 退出二次确认（追加）

托盘「退出」改为 `confirmQuit()`：`dialog.showMessageBox`，`buttons:["退出","取消"]`、
`defaultId/cancelId = 1`（默认焦点与 ESC 都落在取消），`noLink: true`。
`quitConfirming` 标志防连点叠框。

**关键坑：窗口隐藏时不能把 MessageBox 挂成它的子窗口** —— Windows 上模态框会跟着
隐藏父窗口一起不显示，用户会以为「点了退出没反应」。代码里按 `win.isVisible()` 分流：
可见 → `showMessageBox(win, opts)`；隐藏 → `showMessageBox(opts)` 独立弹。

验证方式（探针 `dist-test/probe-quit-dialog.cjs` + `dist-test/find-dialog.py`）：
隐藏窗口后弹框，再枚举顶层窗口断言
`class=#32770 / title=退出 TermAI / IsWindowVisible=true`，PostMessage WM_CLOSE 后
探针拿到 `response=1`（取消）→ 按钮索引语义正确。**不能靠 tasklist 看窗口标题**，
它只报进程主窗口，抓不到 TaskDialog。



## 「63s 模型响应较慢」误报：阶段计时 + 关思考 + 提示词瘦身（dl-20261106e）
**诊断**（用 `agent-runs/1793954371302-s136iw` 的 outputs mtime 还原节奏）：单轮往返 6s~100s 剧烈抖动，
说明不是「模型整体慢」，而是几类时间被混进同一个数字。
1. `useBusySeconds(busy, steps.length)` 只在**步骤数变化**时清零 → 执行命令 / `maybeCompress()` 的
   大输入请求 / 只回 PLAN 不建 step 的轮次（`store/agent.ts` 里 `if (parsed.commands.length === 0) continue`）/
   重连 25s 宽限，全部累加进「模型响应时间」。
2. 每轮固定 9.2k token 系统提示词（probe 实测 `buildAgentSystemPrompt` 11,913 字符 ≈ 9,211 token）。
3. `thinkingDisableExtra` 只认 `qwen3` → 其它思考型模型每轮先烧上千 token 推理，首字 30~60s，
   且常把 4096 max_tokens 吃光 → `finish_reason=length` → `OutputBudgetError` → **maxTokens×4 整轮重生成**。
4. `droppedExtraBody` 是**请求级**变量，而 Agent 在 run 开始时就把 `extraBody` 烘进 `agentConfig`
   → 网关一旦拒该字段，本轮后续每次请求都要再吃一次 400 + 重试。

**改动**
- `store/agent.ts`：新增 `AgentBusyStage`（thinking/exec/compress/confirm/reconnect）+ `bucket.stage/stageSince`，
  `setStage(stage, reset)`；`callModel` 每轮 `setStage("thinking", true)`，执行/压缩/确认/重连各自打点，
  `finally` 清空。续跑时同一阶段也靠 reset 重新计时，PLAN-only 轮次不再累加。
- `src/lib/busyHint.ts`（新）：纯函数出文案与阈值 —— 思考 45s、执行 120s、压缩 20s，只有前两者给警示色；
  `awaiting-confirm` 以 phase 为准。6 条单测。
- `AgentPanel`：`useBusySeconds(busy, stageSince ?? steps.length, stageSince)`，按绝对时间起算（切回来也对），
  标签取自 `busyHint`，窄宽度下 `truncate min-w-0` + 秒数 `whitespace-nowrap`。
- `services/ai.ts`：`thinkingDisableExtra` 改为「除原生 OpenAI（`^(?:[\w.-]+/)?(?:gpt-|o\d)`）外一律发」；
  新增模块级 `thinkingFieldUsable`，被 400/422/**500** 拒过一次就永久停发；`requestChat` 每次尝试前按它剥字段
  （解决「config 早烘好」导致的一轮内反复 400）。
- `prompts.ts`：`AGENT_SYSTEM_PROMPT` 12,395 → 8,029 字符（**9,211 → 5,383 token，-42%**），规则语义全保留。

**验证**：`npm test` **611/611**（+7）；tsc/eslint 干净；preview 截图 `dist-test/preview/busy-4.png` 四态文案正确、

## 「这么简单的事不会写脚本」：批量枚举必须用循环（dl-20261106f）
**现场**：`agent-runs/1793958126279-g7gao0`，目标「按天建 2025-08-01~2025-09-01 的 32 个目录」。
4 步 146s / 47.8k tok：001 步下发 6 段垃圾（`[root@mgt signature]#`、`r`、`m`、`r`、`f`，
6×127）、003 `ls -la` 显示目录为空、004 一条 `mkdir -p` 硬编码 5 个日期，然后宣布「已成功创建」——
实际要 6~7 轮才建得完。

**根因（两层）**
1. **提示词在明令禁止循环**：规则 4 写着「不要写多行 while/for 循环」——那是循环被拼平成一行、
   注释吞掉 `done` 卡死的年代留下的（该问题已由 `needsScriptFile` 落盘脚本解决，规则没同步）。
   于是模型只会手抄路径。
2. **引擎没有对应闸门**：枚举式写法完全合法，去重/空转/风险闸门都看不见它。

**改法**
- `prompts.ts` 规则 4 重写：次数固定 ≤3 手写可以；**次数随目标数量增长必须一次循环做完**，
  给 `for i in $(seq 0 31)` + `date -d` 模板与 `{0801..0901}` 花括号写法，并说明多行会被落盘成脚本
  （所以安全）。同时加「批量写操作同轮末尾附一条验证（`ls -d ... | wc -l`），没看到数量不许宣布完成」。
- `src/lib/bulkEnum.ts`（新）：`findEnumeration()` 按「数字抹成 `#` 后的骨架」聚合，
  单条内 ≥4 个同骨架 token、或多条命令整体同构 ≥4 条 → 判定枚举；`suggestLoopRewrite()` 出改写模板
  （花括号 + date 循环两条路，带真实前缀）。`ENUM_MIN_TARGETS=4`。
- `store/agent.ts`：闸门放在空转判定之前，**只对写操作**（`isStateChanging`，**不是 riskLevel**——
  `mkdir -p` 安全分级是 low，用它当判据会漏掉本案主角）打回，最多 2 次，不计 `lowValueStreak`。
- `services/safety.ts` 新增 `isEchoFragment()`：提示符开头（`[x@y z]#`、`user@host:~$`）或单字符
  片段直接拦，回灌「这是终端回显，不是命令」。

**验证**：`npm test` **625/625**（+14）；tsc/eslint 干净。
- `probe/enum-replay.mjs`：现场那条 `mkdir` 命中 count=5，改写文案正确；循环版/花括号版均不命中。
- `probe/loop-pipeline.mjs`：完整 for 循环 `shellIncomplete=false`、`sanitizeCommandLine` 逐字不变、
  `needsScriptFile=true`；`probe/loop-check` 实跑产出 32 个目录、exit 0（一轮 vs 原来七轮）。
- `probe/gate-check.mjs`：本例闸门触发=true，只读枚举不触发。
**打包**：`release/dl-20261106f`，Setup 69,205,135 B `3c915001…5b558a`，portable 68,649,467 B
`9b99666b…cc8414`；asar 内新串 8 条全中、旧禁令 0；bundle 1,062,407 B 与 dist 一致；冒烟 4 进程。
