## 新增：ProxyJump 多跳 + 自动重连 + AI 流式输出（P0 收尾，用户指令"全部帮我做"）

### 1. ProxyJump 多跳（主进程 ssh.ts）
- `acquireJump(params)`：先连跳板机 `Client`，用 `forwardOut` 拿 `sock` 作为目标连接 `sock` 参数实现多跳；`Session.jumpClient` 记录并在 `disconnect/disposeAll` 清理。
- `SshConnectParams.proxyJump?: SshProxyJumpConfig`（含 host/port/username/auth/privateKey/passphrase）。
- 渲染：`HostConfig.proxyJumpHostId`；`HostPanel.doConnect` 解析引用主机为 `proxyJump`；`HostFormModal` 加跳板机下拉；preload 类型 `SshProxyJumpConfig`。

### 2. 自动重连 + keepalive（主进程 ssh.ts）
- `buildConnectConfig` 加 `keepaliveInterval:30000` + `keepaliveCountMax:8`。
- `connect` 非主动断开（非 `intentional`）按指数退避自动重连（上限 8 次 / 上限 90s），重建 shell 并复用 sessionId 通道；`emit ssh:status reconnecting/reconnected`。
- `disconnect/disposeAll` 置 `intentional=true` 避免误重连；`Session.reconnectAttempts/reconnecting/intentional` 字段。
- 渲染：`connecting` 后若收到 `reconnecting` 状态显示橙色"重连中"徽标（XTerminal）。

### 3. AI 流式输出（ai.ts + agent 链路）
- `ai.ts` 重写 `chatCompletionRaw`：检测 `stream:true` + SSE `Content-Type`，用 `ReadableStream` 边读边解析 `parseSseStream`，`onToken` 回调增量文本；非流式/非 SSE 走原兜底。
- `chatCompletion`/`chatCompletionOpenAI` 透传 `onToken`；`chatCompletionOpenAI` 跳过空 content 消息（避免流式占位污染历史）。
- Agent：`useSessionAgent` 暴露 `liveThought`；循环内 `chatCompletionRaw` 接 `onToken` 实时写入 `liveThought`，每条回复消费后清空。
- UI：`AISidebar.send` 用占位消息 + `updateMessage` 流式渲染；`AgentPanel` 新增 `LiveThoughtCard`（流式思考过程，呼吸光标）。

## 新增：P2 分屏多标签（用户从 P2 清单选"分屏多标签"）

> 多标签原本就有（会话 Tab），本轮核心是**分屏**：一个终端区同时并排/堆叠显示多个会话。

### 关键设计（重要，别改错）
**所有会话的 XTerminal 始终挂载在同一个容器里，只用绝对定位摆到各面板矩形，绝不按面板卸载/重挂载。**
- 依据：XTerminal 卸载时只做 `disposed/unregister/ro.disconnect`，**不会**断开 SSH 或销毁 PTY；但重挂载会重建 xterm、丢回显并可能重触发连接逻辑。
- 面板尺寸变化由 XTerminal 内部已有的 ResizeObserver 自动 `fitAndSync()`（含同步 PTY 尺寸），无需额外处理；尺寸为 0（隐藏）时它自己会跳过。
- 未展示的会话保持 `display:none`，与原「全部挂载只隐藏非活跃」的行为一致。

### 改动文件
- `src/lib/splitLayout.ts`（新）：纯函数。二叉树 `SplitNode = SplitLeaf | SplitBranch`；`direction: "row"(左右) | "column"(上下)`；不可变树操作 `splitPane`/`closePane`/`setPaneSession`/`setRatio`/`mapLeaves`/`listLeaves`/`findLeaf`/`findLeafBySession`；`computeLayout` 算出每个叶子的矩形与每条分隔线位置，**全部是 0~1 分数，无需测量 DOM**。

## 新增：P2 Agent 上下文压缩质量调优（用户从 P2 清单选"Agent上下文压缩质量调优"）

### 旧实现的 5 个坑（逐个修掉）
1. **触发只看条数**（`messages.length >= 18`）—— 一条 4 万字符的工具输出和一句"好的"权重相同，最该压缩的情况反而漏防。
2. **自由文本摘要** —— 关键路径/端口/错误码容易在改写中丢失。
3. **二次压缩把上一轮摘要当普通消息再压一遍** —— 每压一次丢一层，多轮任务信息逐轮衰减。
4. **原始任务目标会被压进摘要** —— 模型跑到十几轮后忘了最初要干什么。
5. **摘要可能比原文还长** —— 白花一次调用。

### 改动文件
- `src/lib/contextCompression.ts`（新，纯函数）：
  - `ChatMessage` 类型迁到这里作为**唯一定义**（原在 agent.ts 内部未导出，已改为 import，避免类型分叉）。
  - `estimateTokens`/`estimateMessagesTokens`：中英混合估算（CJK ×1.5 token/字，其余 ÷4，每条 +4 结构开销），只用于相对判断。
  - `shouldCompress(messages, {maxMessages, maxTokens})`：**条数或估算 token 任一超标即触发**。注意下界只能用 `< 3`，用 `< 4` 会把「2~3 条但每条超大」挡在门外（单测抓到过）。
  - `renderTranscript`：单条超 1600 字符时**头尾保留、中间省略**（命令在头、结果/报错在尾），既保住关键信息也控制压缩调用成本。
  - `buildCompressionMessages`：结构化六段式提示词（任务目标/已完成步骤/关键事实/错误与解决/当前状态/待办），明确要求命令保持原文、未解决错误要突出；有 `previousSummary` 时走**滚动合并**分支。
  - `assembleCompressedMessages`：system → 摘要 → **固定插入目标** → 最近轮；目标去重按**内容**（不限 role，按 role 会漏判）。
  - `clampSummary`（上限 2200 字符）、`trimMessages`（硬截断兜底，同样保住目标）。
- `src/lib/contextCompression.test.ts`（新）：26 例单测。
- `src/store/agent.ts`：`maybeCompress` 重写 —— 双条件触发、滚动合并、目标固定、**压缩后收益校验**（`estimateMessagesTokens(next) >= 原` 则回退硬截断）；本地 `trimMessages` 重命名为 `hardTrim` 并改为调用纯函数版本（8 处调用点全部同步改）。

### 阈值
`COMPRESS_TRIGGER = 18` 条、`MAX_CONTEXT_TOKENS = 40000`（估算）、`KEEP_RECENT = 8`、`MAX_AGENT_MESSAGES = 22`。

### 调优时踩到的两个自测发现的缺陷（说明单测有价值）
- `shouldCompress` 原本 `if (messages.length < 4) return false` 直接挡掉了 token 触发分支 —— 单测「条数少但内容超长也触发」暴露。
- 目标去重原为 `m.role === "user" && m.content === goal` —— 目标文本出现在 assistant 消息里时会重复插入。改为只比内容。
