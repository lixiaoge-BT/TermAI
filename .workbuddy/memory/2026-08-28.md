# 2026-08-28 TermAI 开发记录

## 新增 AI「终端接管 Agent」模式（AI 助手双模式）
- 需求：AI 助手分两个模式 —— ① 原有 AI 问答；② 连接主机后 AI 自动接管终端，用户说「分析系统资源」，AI 自己决定并执行一系列命令、读取输出、最后给出分析与建议总结。
- 新增文件：
  - `src/lib/terminalBus.ts`：终端输出广播总线（`emitTerminalOutput` / `subscribeTerminalOutput`）。XTerminal 在 SSH/本地 `onData` 里广播已 stripAnsi 的增量输出。原因：`session.recentOutput` 会被裁剪到 200 行，长任务输出会丢，Agent 必须订阅原始增量流。
  - `src/services/agent.ts`：Agent 执行引擎。
    - `parseAgentReply()`：解析 `<<<RUN>>>cmd<<<END>>>` / `<<<DONE>>>` 协议；模型不按协议输出时退化为「整段即结论」，避免死循环。
    - `execCommand()`：用哨兵包裹命令真实下发到终端并可靠取回输出。
      - 普通命令：`echo "TERMAI_BEGIN_x"; <cmd> 2>&1; echo "TERMAI_EXIT_x:$?"; echo "TERMAI_END_x"`
      - BEGIN/END 匹配要求「独占一行」，以此跳过 PTY 对整条脚本的回显
      - heredoc/多行脚本 → 落盘 `/tmp/termai_agent_x.sh` 再 `bash` 执行，结束后 `rm -f`
      - 写 PTY 时把脚本换行统一转成 `\r`（终端里回车是 `\r`）
      - 超时（默认 30s）/中断时退化为返回已收集输出
  - `src/store/agent.ts`：Agent 状态机与循环（思考 → 安全审查 → 必要时用户确认 → 执行 → 回传观察 → 收敛总结）。支持最大步数（默认 8）、停止、中风险自动执行开关。
  - `src/components/AgentPanel.tsx`：Agent UI（快捷任务、步骤时间线、实时输出、风险确认卡片、Markdown 总结、复制）。
  - `src/lib/markdown.ts`：极简 Markdown → HTML（先转义），供总结渲染。
- 修改文件：
  - `src/components/XTerminal.tsx`：ssh/local `onData` 中增加 `emitTerminalOutput(sessionId, cleaned)`。
  - `src/services/ai.ts`：抽出 `callOpenAIChat`，新增 `chatCompletionRaw()`（自定义 system prompt + 完整 messages），供 Agent 多轮循环使用。
  - `src/services/prompts.ts`：新增 `AGENT_SYSTEM_PROMPT`、`buildAgentSystemPrompt()` 和协议标记常量。
  - `src/components/AISidebar.tsx`：顶部新增「AI 问答 / Agent 接管」模式切换（两个面板保持挂载、用 display 切换以保留上下文）。
  - `src/pages/Home.tsx`：QuickAskBridge 派发 `termai:ai-mode` 事件，把侧边栏切回问答模式。
- 风险策略：none/low 自动执行；medium 由「中风险自动执行」开关决定；high/critical 必须弹确认（可执行/跳过/终止）。生产标签主机在提示词里强制只读诊断。

## AI 助手按终端会话隔离 + Agent 输入框清空
- 需求：1) Agent 任务完成后输入框里的目标文本要清空；2) 不同终端标签页要有各自独立的 AI 问答/Agent 记录，随标签页切换而切换。
- 改动：
  - `src/store/chat.ts`：重构为按 sessionId 分桶 `buckets: Record<string, ChatBucket>`（messages/isLoading/error），新增 `useSessionChat(sessionId)` 与 `currentChatKey()`；无会话时落到 `GLOBAL_CHAT_KEY = "__global__"`。读取用稳定空桶常量，避免在渲染期写 store 造成重复渲染；写入时才创建桶。
  - `src/store/agent.ts`：同样改为 `buckets: Record<string, AgentBucket>`，`run/stop/resolveConfirm/reset` 都接收 sessionId 并在任务启动时锁定该会话（不再用 `getActiveSession()`，避免切标签页串台）；新增 `dispose(sessionId)` 中断任务并释放资源；`maxSteps/autoRunMedium/commandTimeoutMs` 仍为全局共享设置。新增 `useSessionAgent(sessionId)`。
  - `AgentBucket` 增加 `submittedGoal`：任务提交时快照目标，完成后清空 `goal`（输入框），面板顶部仍显示「任务目标」卡片保留上下文。仅 `phase==="done"` 时清空；失败/终止保留输入便于改后重试。
  - `src/components/AISidebar.tsx`：ChatArea 改用 `useSessionChat(session?.id)`；欢迎语改为按 chatKey 用 Set 记录（每个会话各一次）；切换会话时清空草稿输入框。
  - `src/components/AgentPanel.tsx`：改用 `useSessionAgent(session?.id)`，新增「任务目标」卡片。
  - `src/pages/Home.tsx`：QuickAskBridge 改为在事件触发时读取当前激活会话并写入对应桶（不再用 ctxRef 缓存全局状态）；StatusBar 的「AI 对话 N 条」改为统计当前会话；`closeTab` 里调用 `useAgentStore.getState().dispose(id)` + `useChatStore.getState().removeBucket(id)`。

## 补充：asar 里混入旧 bundle 的根因
- `vite.config.ts` 里显式设了 `build.emptyOutDir: false`，所以每次 build 不会清理 `dist/assets/`，旧 hash 的 js/css/map 会一直累积并被 electron-builder 打进 asar（本次包里混进了上一版的 `index-CHQWurZX.js`）。
- 影响：包变大、验证时 grep 到旧代码会误判。功能上无害（index.html 只引用当前 hash）。
- 处理：打包前手动 `rm -f dist/assets/index-*.js dist/assets/index-*.css`（保留本轮刚产出的那组 hash 文件）再 `npx electron-builder`。改 `emptyOutDir` 会影响既有构建语义，暂未动，需要时再与用户确认。

## 踩坑：electron-builder 卡在 packaging（重要）
- 现象：`npm run dist` 在 `• packaging platform=win32 ...` 或 `output file is locked for writing` 处挂住 18+ 分钟无进展，node 进程 CPU 为 0，只能 kill。连续两次复现。
- 根因：**输出目录里已存在上一次的产物**（`release/0.1.0/win-unpacked` 整个目录 + 两个 exe），electron-builder 需要覆盖/删除这些大文件时被占用（病毒扫描/句柄/sandbox 删除拦截），于是无限等待解锁。
- 解法（清理后 2 分 47 秒就构建完）：
  1. `rm -rf release/0.1.0/win-unpacked`（纯中间产物，必然可重建）
  2. 把旧的 `TermAI 0.1.0.exe` / `TermAI Setup 0.1.0.exe` 先 `mv` 成 `*.prev.exe`，让输出路径空出来（不要直接删，构建失败还能改回来）
  3. 确认 `dist/assets/` 只有当前这次 build 产生的那一组 hash 文件（vite 默认会清空 dist，但手动确认一次更稳）
  4. 用 `env -u NODE_OPTIONS npm run dist` 或 `NODE_OPTIONS= npm run dist` 绕过 sandbox 的 safe-delete 拦截
  5. 构建成功后 `.prev.exe` 可删；用 `npx asar extract` 解包 `win-unpacked/resources/app.asar`，grep 新功能的关键字符串确认真的进了产物
- 另：项目根目录残留了 4 个 `tmp-asar-check*` 解包目录（历次验证留下的），可清理。

## 修复：termai:quick-ask 事件被重复处理
- 现象（代码审查发现的既有 bug）：`AISidebar` 的 ChatArea 与 `Home` 的 `QuickAskBridge` 同时监听 `termai:quick-ask`，同一次终端 `?提问` 会被两个监听器各发一次 AI 请求，对话里出现重复的用户/助手消息。
- 修复：移除 ChatArea 内那份监听（连同 `sendRef`），保留 Home 的 QuickAskBridge 作为全局唯一处理者；它由 Home 保证始终挂载，因此 AI 侧边栏收起时依然可用。
