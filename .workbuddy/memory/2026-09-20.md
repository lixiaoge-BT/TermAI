## TermAI 安装版「首次失败、二次才成功」根因分析（已确认）

现象：运行 NSIS 安装器首次点「安装」窗口直接消失、什么都没装；第二次运行才成功。用户 9/20 重装时一次成功，反向印证了根因。

- 安装器为 electron-builder 默认 NSIS（`package.json:128-140`，`perMachine:false` → 装到 `%LOCALAPPDATA%\Programs\TermAI`；`signingHashAlgorithms:[]` 未签名）。
- 关键逻辑：`node_modules/app-builder-lib/templates/nsis/include/allowOnlyOneInstallerInstance.nsh:50-118` 的 `_CHECK_APP_RUNNING` —— 覆盖安装（`isUpdated`）时**不弹提示、静默 `taskkill TermAI.exe` 仅 Sleep 300ms 就覆盖文件**；`.onInit` 还有 `APP_GUID` 安装器互斥锁。
- 结论：时好时坏 = 安装瞬间存在残留 `TermAI.exe` 进程/子进程（conhost）或上一次安装的 setup 互斥锁，占住 `TermAI.exe` 导致覆盖失败→整段回滚退出；首次尝试清掉了占用，二次运行已无占用→成功。属安装时进程/文件锁竞态，**非应用代码 bug**。
- 验证方法（若再复发）：重装前确认任务管理器无 `TermAI.exe`/`conhost` 子进程；看 Windows 安全中心保护历史有无 `TermAI.exe` 被隔离（未签名 Defender 拦截）；Process Monitor 过滤 `TermAI` + `SHARING VIOLATION`。
- 根治方向（未实施，用户未要求）：安装前强制结束并确认进程退出再覆盖、暂设 `runAfterFinish:false`、或对构建签名/加 Defender 排除项。
