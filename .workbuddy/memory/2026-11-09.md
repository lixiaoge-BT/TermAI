# 2026-11-09

## 崩溃排查（用户报「软件特别容易崩，直接退出」）

### 证据链
- **主程序原生崩溃 17 次**：`TermAI.exe`，异常码 `c0000409`（FAST_FAIL_FATAL_APP_EXIT，
  Chromium `CHECK` 主动自杀），`Sig[6]` 偏移 **全部相同 `0x4613e15`** → 确定性 bug 不是 OOM。
  时间 08-25 → 09-20 后终止；崩溃报告的 FileVersion 是 `31.3.1.0`（未打版本号的旧包），
  现包已是 `0.1.0`。无 minidump（当时没启 crashReporter）→ 无法符号化。
- **安装器崩溃**（最近 11-04 / 11-06，"直接退出"的真身之一）：`TermAI Setup 0.1.0.exe`，
  故障模块 **System.dll**（NSIS System 插件），启动后 1.2–1.7s 崩。
  根因：`allowOnlyOneInstallerInstance.nsh` → `getProcessInfo.nsh` 用 `System::Call ... *i $R8`
  把「长度值」当指针传；且原进程检测 `nsExec::Exec %SYSTEMROOT%\...` **不展开环境变量**
  （探针实测返回 `error`）→ 永远判「未运行」。
- **零现场**：打包版 console 全 noop + GUI 无 stdout + crashReporter 未启动。

### 修复
- `build/installer.nsh`：改用 `$SYSDIR` 绝对路径；taskkill `/f /t` + 1s 轮询 ≤15；
  `MessageBox /SD IDOK`（`/SD IDCANCEL` 会让 `/S` 直接取消退出 exit=2）。
- `electron/main/diagnostics.ts`（新）：crashReporter + `logs/crash.log` + `logs/mem.log`(30s) +
  `render-process-gone` 落盘并自动 reload×2 + `app.quit` 调用栈 + 退出事件链；
  `uncaughtException` 只弹一次框（原实现每次弹 → 像卡死）。
- `electron/main/index.ts`：ready 前 `installDiagnostics()`，建窗后 `watchRenderer()`。

### 实测
- 干净静默安装 `exit=0`，20 个文件；**程序运行中覆盖安装** `exit=0`（先杀进程再装，无崩溃记录）。
- 打包版 `crash.log` 正常落盘；`app.quit` patch 不影响退出（探针 quit 链路全触发，exitCode=0）。
- 门禁 625/625 + eslint 0 + tsc 0；包 `release/dl-20261106h`。

### 踩坑
- **`/D=` 参数反斜杠会被 shell 吞掉** → 变成 `D:Traedist-testiprobe3`（相对路径）。
  安装位置写进 `HKCU\Software\<APP_GUID>` 的 `InstallLocation` 且**有粘性**，
  下一次不带 `/D` 的安装会在错误目录里再套一层。清理要同时删
  `HKCU\Software\<GUID>` 与 `HKCU\...\Uninstall\<GUID>`。
- NSIS 探针必须写 `RequestExecutionLevel user`，否则非交互会话执行报 `Permission denied(126)`。
- `cmd /c` 在 Bash 里被安全策略拦；`cmd //c` + `MSYS_NO_PATHCONV=1` 会退化成交互 shell。
