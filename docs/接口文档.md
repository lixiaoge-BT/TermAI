# TermAI 接口文档

> 版本：v0.1.0 · 更新时间：2026-09-01
> 适用代码：`electron/`（主进程）+ `src/`（渲染进程）

---

## 1. 概述

TermAI 是一个 Electron 应用，进程间只有一条通道：**preload 脚本用 `contextBridge` 暴露的 `window.*` API**。渲染进程不直接碰 Node/Electron，所有系统能力（SSH、PTY、文件系统、加密、落盘）都通过 IPC 调用主进程完成。

```
┌─────────────────────────────────────────────────────┐
│  渲染进程 (React)                                    │
│  src/components  src/store  src/services  src/lib    │
└───────────────────┬─────────────────────────────────┘
                    │  window.ssh / sftp / localFs ...
                    │  (contextBridge, electron/preload/index.ts)
┌───────────────────▼─────────────────────────────────┐
│  主进程 (Node)                                       │
│  ssh.ts (ssh2)  localTerminal.ts (node-pty)          │
│  localFs.ts (fs)  recordings.ts  socks5.ts           │
│  safeStorage (Electron)                              │
└─────────────────────────────────────────────────────┘
```

### 1.1 通信约定

| 约定 | 说明 |
| --- | --- |
| 请求-响应 | 渲染进程 `ipcRenderer.invoke(channel, ...args)` → 主进程 `ipcMain.handle(channel, handler)`，返回 `Promise` |
| 主进程推送 | 主进程 `webContents.send(channel, ...args)` → 渲染进程 `ipcRenderer.on(channel, cb)` |
| 取消订阅 | 所有 `onXxx()` 返回的都是 **取消订阅函数**，直接调用即可解绑，不要在组件里手动 `ipcRenderer.off` |
| 异常 | 主进程 `throw` 的 `Error` 会变成渲染进程 `invoke()` 的 rejected Promise，`err.message` 可直接展示给用户 |
| 会话寻址 | SSH / 本地终端 / SFTP 全部以 `sessionId`（字符串）为键，多会话互不干扰 |
| 通道命名 | `域:动作`，如 `ssh:connect`、`local-fs:list-dir`、`recording:save` |

### 1.2 全局对象一览

| 全局对象 | 来源 | 职责 |
| --- | --- | --- |
| `window.ssh` | `electron/preload/index.ts` | SSH 会话生命周期、IO、端口转发 |
| `window.localTerminal` | 同上 | 本地 PTY 终端（PowerShell / bash / zsh） |
| `window.sftp` | 同上 | 远程文件浏览与传输 |
| `window.localFs` | 同上 | 本机文件系统浏览与操作 |
| `window.secureStorage` | 同上 | 凭据静态加密 / 解密（safeStorage） |
| `window.recordings` | 同上 | 操作记录库的读写（JSON 落盘） |
| `window.termAI` | 同上 | 应用级窗口操作 |
| `window.clipboard` | 同上 | 剪贴板读写 |
| `window.__termai_debug` | 同上 | 调试用 ping |

TypeScript 类型声明见 `src/types/index.ts`，通过 `declare global { interface Window }` 挂载。

## 2. `window.ssh` — SSH 会话

### 2.1 连接管理

#### `ssh.connect(sessionId, params): Promise<boolean>`

建立 SSH 连接并分配 PTY。

```ts
interface SshConnectParams {
  host: string;
  port: number;
  username: string;
  password?: string;          // authMethod = password 时
  privateKey?: string;        // authMethod = privateKey 时，PEM 全文
  passphrase?: string;        // 私钥口令
  cols?: number;              // 前端 xterm 真实列数
  rows?: number;              // 前端 xterm 真实行数
  proxyJump?: SshProxyJumpConfig;  // 跳板机
}

interface SshProxyJumpConfig {
  host: string;
  port: number;
  username: string;
  password?: string;
  privateKey?: string;
  passphrase?: string;
}
```

**注意**：`cols` / `rows` 必须在建连时传入。否则远端 PTY 停留在默认 80×24，长命令换行和历史命令重绘会整体错位。

**ProxyJump 行为**：先连到 `proxyJump.host`，再从跳板机内部转发到目标 `host:port`，用于「本机 → 跳板机 → 内网目标」的多跳场景。跳板机的完整认证信息由前端从已保存的主机配置里解析后拼进来。

返回 `true` 表示 shell 已就绪。失败时抛出 Error（认证失败、网络不可达、跳板机不通等）。

#### `ssh.disconnect(sessionId): Promise<boolean>`

断开并清理该会话的 PTY、SFTP、所有端口转发。

#### `ssh.listSessions(): Promise<SshSessionInfo[]>`

```ts
interface SshSessionInfo {
  id: string;
  host: string;
  username: string;
  connected: boolean;
  startTime: number;
}
```

### 2.2 数据读写

#### `ssh.write(sessionId, data): Promise<boolean>`

向远端 shell 写入原始输入（含转义序列、Ctrl 组合键编码）。

#### `ssh.resize(sessionId, cols, rows): Promise<boolean>`

同步 PTY 窗口尺寸。终端容器尺寸变化时必须调用，否则远端不重排。

### 2.3 端口转发

#### `ssh.forwardLocal(sessionId, spec): Promise<SshForwardStatus>`
本地端口转发（`-L`）：监听本机 `localPort`，流量经 SSH 隧道到 `remoteAddress:remotePort`。

#### `ssh.forwardRemote(sessionId, spec): Promise<SshForwardStatus>`
远程端口转发（`-R`）：在远端监听端口，流量回到本机目标。

#### `ssh.forwardDynamic(sessionId, spec): Promise<SshForwardStatus>`
动态转发（`-D`）：在本地起一个 **SOCKS5 代理**（`electron/main/socks5.ts`），目标地址由 SOCKS 客户端连接时动态指定。

```ts
type SshForwardType = "local" | "remote" | "dynamic";

interface SshForwardSpec {
  id?: string;                // 不传则服务端生成
  type: SshForwardType;
  localAddress?: string;      // local / dynamic 的监听地址，默认 127.0.0.1
  localPort: number;          // local / dynamic：0 表示随机分配
  remoteAddress: string;      // dynamic 时忽略
  remotePort: number;         // dynamic 时忽略
}

interface SshForwardStatus {
  id: string;
  type: SshForwardType;
  localAddress?: string;
  localPort?: number;
  remoteAddress?: string;
  remotePort?: number;
  bindAddress?: string;       // 实际绑定地址
  bindPort?: number;          // 实际绑定端口（localPort=0 时回填）
  listening: boolean;
  error?: string;
}
```

#### `ssh.listForwards(sessionId): Promise<SshForwardStatus[]>`
#### `ssh.cancelForward(sessionId, id): Promise<boolean>`

### 2.4 事件订阅

```ts
// 远端 shell 输出（已解码字符串，非 Buffer）
const off = window.ssh.onData((sessionId: string, data: string) => { /* ... */ });

// 连接状态变化
const off2 = window.ssh.onStatus((sessionId: string, status: string, extra?: unknown) => { /* ... */ });

// 转发状态变化（建立 / 失败 / 断开）
const off3 = window.ssh.onForward((sessionId: string, status: SshForwardStatus) => { /* ... */ });

off(); off2(); off3();   // 取消订阅
```

`onStatus` 的 `status` 取值与 `TerminalSessionState.status` 对齐：
`connecting` → `connected` → `reconnecting` / `disconnected` / `error`。
`error` 时 `extra` 携带错误描述。

## 3. `window.localTerminal` — 本地 PTY 终端

基于 `node-pty`，Windows 下默认 PowerShell，Unix 下取 `$SHELL` 或 `/bin/bash`。

| 方法 | 签名 | 说明 |
| --- | --- | --- |
| `create` | `(sessionId, shell?, cols?, rows?) => Promise<boolean>` | 创建 PTY。`shell` 省略则用系统默认 |
| `write` | `(sessionId, data) => Promise<boolean>` | 写入输入 |
| `resize` | `(sessionId, cols, rows) => Promise<boolean>` | 调整窗口 |
| `dispose` | `(sessionId) => Promise<boolean>` | 销毁 PTY，释放进程 |

事件：

```ts
window.localTerminal.onData((sessionId: string, data: string) => {});   // 输出
window.localTerminal.onReady((sessionId: string) => {});                // PTY 就绪
window.localTerminal.onExit((sessionId: string, exitCode: number) => {}); // shell 退出
window.localTerminal.onError((sessionId: string, error: string) => {});  // 异常
```

## 4. `window.sftp` — 远程文件（SFTP）

SFTP 复用 SSH 连接，但需要先显式 `connect` 建立独立 SFTP 通道。

| 方法 | 签名 | 说明 |
| --- | --- | --- |
| `connect` | `(sessionId, params: SshConnectParams) => Promise<boolean>` | 建立 SFTP 通道（参数同 `ssh.connect`） |
| `list` | `(sessionId, path) => Promise<RemoteFileInfo[]>` | 列目录 |
| `mkdir` | `(sessionId, path) => Promise<void>` | 新建目录 |

| `download` | `(sessionId, remotePath, localPath) => Promise<void>` | 下载 |
| `upload` | `(sessionId, localPath, remotePath) => Promise<void>` | 上传 |

## 6. `window.secureStorage` — 凭据加密

基于 Electron `safeStorage`（Windows: DPAPI / macOS: Keychain / Linux: libsecret）。

```ts
secureStorage.encrypt(plain: string): Promise<string>   // 返回 "ENC:<base64>" 或降级为原文
secureStorage.decrypt(cipher: string): Promise<string>   // 自动识别 ENC: 前缀
```

约定：

- 加密成功返回 `ENC:` + base64；失败或平台不支持时**原样返回明文**（保证功能可用，UI 层提示降级）
- 解密时若无 `ENC:` 前缀按旧明文处理，保证老版本配置升级平滑
- 该接口被 `src/lib/secureStorage.ts` 包装成 zustand `persist` 的 `StateStorage`，主机密码、私钥、AI API Key 落盘前自动加密

## 9. 前端服务层 API（`src/services`）

这一层跑在渲染进程，是 UI 与能力之间的业务封装。

### 9.1 `services/ai.ts` — AI 对话

#### `chatCompletion(params): Promise<ChatCompletionResult>`

统一的 AI 聊天入口（侧边栏「AI 问答」使用）。

```ts
interface ChatCompletionParams {
  config: AIProviderConfig;
  userMessage: string;
  chatHistory: AIMessage[];
  terminalCtx?: TerminalSessionState | null;   // 注入终端上下文
  hostConfig?: HostConfig | null;              // 注入主机标签（生产环境判定）
  signal?: AbortSignal;                        // 取消（"停止生成"按钮）
  onToken?: (delta: string) => void;           // 提供则走 SSE 流式
}

interface ChatCompletionResult {
  content: string;
  commands: ParsedCommand[];
}
```

- 未配置 `apiKey` 直接抛错：`还未配置 AI API Key，请在上方设置中填写后再试。`
- 只取最近 20 条历史（约 10 轮）送入模型，空内容消息会被跳过（避免流式占位消息污染上下文）
- 终端上下文通过 `buildContextBlock()` 注入 system prompt，包含主机 IP/主机名/当前用户/标签/最近输出/命令历史
- 返回前对全文跑 `parseCommandsFromMarkdown()`，把 ```bash 代码块抽成命令卡片

#### `chatCompletionRaw(params): Promise<string>`

原始接口，`messages` 完全由调用方构造。**Agent 执行循环专用**。

```ts
interface RawChatCompletionParams {
  config: AIProviderConfig;
  messages: Array<{ role: "system" | "user" | "assistant"; content: string }>;
  signal?: AbortSignal;
  onToken?: (delta: string) => void;
}
```

#### 底层请求细节

```
POST {baseUrl}/chat/completions
Authorization: Bearer {apiKey}
Content-Type: application/json

{
  "model": "...",
  "messages": [...],
  "temperature": 0.7,
  "max_tokens": 2048,
  "stream": true | false      // 取决于是否传 onToken
}
```

- `baseUrl` 结尾的 `/` 会被自动去掉
- HTTP 非 2xx 时尝试解析 `json.error.message`，抛出 `AI 请求失败：${msg}`
- 流式模式逐行解析 SSE `data:` 帧，单行 JSON 解析失败会跳过而非中断整轮
- `provider = "anthropic"` 当前未实现，抛错提示改用 OpenAI 兼容 API

### 9.2 `services/agent.ts` — Agent 执行引擎

终端是流式 PTY，没有「命令返回值」的概念。这里用**哨兵协议**从数据流中精确切出命令输出与退出码。

#### `execCommand(sessionId, command, opts?): Promise<ExecResult>`

```ts
interface ExecOptions {
  timeoutMs?: number;      // 基础超时，默认 20000；超时后若仍在持续输出会自动延长
  maxTimeoutMs?: number;   // 硬上限，默认 60000
  signal?: AbortSignal;
  onOutput?: (output: string) => void;   // 实时输出（已清理 ANSI）
}

interface ExecResult {
  output: string;
  exitCode: number | null;
  timedOut: boolean;
  script: string;      // 实际下发的完整脚本（含哨兵），用于 UI 展示
  error?: string;      // 执行本身异常（区别于命令返回非 0）
}
```

实现要点：
- 用 `echo` 打 `TERMAI_BEGIN_<token>` / `TERMAI_EXIT_<token>=<code>` / `TERMAI_END_<token>` 三个唯一哨兵
- BEGIN/END 要求独占一行匹配，从而跳过 PTY 对整条脚本的回显
- 支持 heredoc / 多行脚本：落盘为临时脚本执行，结束后自动清理
- 超时或中断时退化为返回已收集到的全部输出，不抛异常

#### `execCommandBatch(sessionId, commands, opts?): Promise<ExecResult[]>`

批量执行一组彼此无依赖的只读命令，一次往返跑完，把多次 AI 交互压缩成一次。

#### Agent 回复协议解析

```ts
// 模型必须按协议输出，三个标记由 prompts.ts 导出
AGENT_RUN_START = "<<<RUN>>>"
AGENT_RUN_END   = "<<<END>>>"
AGENT_DONE      = "<<<DONE>>>"

interface AgentReply {
  thought: string;          // 命令之前的思考说明
  commands: string[];       // 本次要执行的命令（批量探测时多条）
  done: boolean;
  finalAnswer: string | null;
  raw: string;
}

parseAgentReply(text: string): AgentReply
splitCommandBlock(block: string): string[]   // 容忍模型加的序号/列表符号
```

容错策略（避免死循环）：
1. 命中 `<<<DONE>>>` → 结束，其前的命令作废，以结论为准
2. 命中完整 `<<<RUN>>>...<<<END>>>` 且解析出命令 → 执行
3. 兜底 1：只有开标记没有闭标记 → 从开标记截取到结尾解析
4. 兜底 2：完全没按协议 → 整段当作最终结论，`done = true`

#### `flattenCommand(cmd): string`

把 AI 偶尔输出的多行命令折叠成单行。上一行以 `&& || | ; &` 结尾或当前行是 `then/do/fi/done` 等关键字时用空格拼接，否则用 `;` 分隔。

#### `buildObservation(...)`

把 `ExecResult[]` 组装成回传给模型的观察文本（命令 + 输出 + 退出码）。

### 9.3 `services/safety.ts` — 命令安全审查

本地规则，不依赖 AI。

```ts
type RiskLevel = "none" | "low" | "medium" | "high" | "critical";

interface CommandReviewResult {
  command: string;
  riskLevel: RiskLevel;
  isSafe: boolean;
  requireConfirmation: boolean;
  riskDescription: string;
  confirmationItems: string[];   // 二次确认时必须勾选的项
}

reviewCommand(
  command: string,
  opts?: { isProduction?: boolean; privilege?: "root" | "sudoer" | "user" }
): CommandReviewResult

parseCommandsFromMarkdown(text: string): ParsedCommand[]
```

判定顺序：

1. **空命令** → `none`，安全
2. **高危模式匹配** → 取 `DANGEROUS_PATTERNS` 中的规则（`rm -rf /`、格式化、`DROP DATABASE`、卸载 glibc/systemd 等），风险等级 `high` / `critical`，强制二次确认。若主机标签命中生产环境，确认项最前面插入「⚠️ 当前为主机已标注【生产环境】」
3. **只读命令** → `READONLY_COMMANDS` 白名单（ls / cat / grep / ps / df / ss …），`low`，放行。管道组合要求每一段都只读才算安全；含 `>` 重定向一律不算只读；自动剥掉 `sudo/doas/pkexec` 前缀
4. **其他写操作** → `medium`，生产环境默认需确认

## 13. 自定义窗口事件（`window` DOM 事件）

| --- | --- | --- | --- |

## 14. 错误处理约定

| 场景 | 表现 |
| --- | --- |
| SSH 认证失败 / 网络不可达 | `ssh.connect` reject，`err.message` 直接展示在终端面板 |
| Manager 未初始化 | 抛 `XX Manager 未初始化`（主进程尚未 ready 时调用） |
| AI 未配置 Key | 抛 `还未配置 AI API Key，请在上方设置中填写后再试。` |
| AI HTTP 错误 | 抛 `AI 请求失败：HTTP 4xx` 或 `AI 请求失败：{服务端 message}` |
| AI 请求被取消 | `AbortError`，UI 显示 `_请求已取消_` |
| 命令执行超时 | 不抛异常，`ExecResult.timedOut = true`，返回已收集到的输出 |
| 加密平台不支持 | 静默降级为明文存储，UI 提示 |
